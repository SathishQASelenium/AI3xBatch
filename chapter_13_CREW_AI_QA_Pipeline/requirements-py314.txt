# Python 3.14 WORKAROUND LOCK - not a replacement for requirements.txt
# ===========================================================================

# requirements.txt is the supported install. Use it on Python 3.11 or 3.13,
# which is what the Dockerfile (python:3.13-slim) and CI (3.11, 3.13) use.
# Use THIS file only on a machine where 3.14 is the only interpreter.
#
# ---------------------------------------------------------------------------
# THIS FILE WILL NOT INSTALL WITH pip. That is expected, not a bug.
# ---------------------------------------------------------------------------
# crewai declares Requires-Python >=3.10,<3.14. pip checks that metadata before
# it considers a candidate, so an exact pin does not help:
#
#     ERROR: Could not find a version that satisfies the requirement
#            crewai==1.15.17
#
# Pinning cannot bypass a Requires-Python gate. Only uv, told to resolve for
# 3.13, gets past it. Everything below follows from that one override.
#
# ---------------------------------------------------------------------------
# Install (Windows, PowerShell)
# ---------------------------------------------------------------------------
#   uv venv .venv --python 3.14
#   uv pip install --python .venv\Scripts\python.exe --python-version 3.13 -r requirements-py314.txt
#
#   # Resolving for 3.13 downloads cp313 binary wheels, which CANNOT load on
#   # 3.14 (first symptom: ModuleNotFoundError: pydantic_core._pydantic_core).
#   # Reinstall every compiled package natively so uv fetches cp314 wheels:
#   uv pip install --python .venv\Scripts\python.exe --reinstall `
#     pillow cffi aiohttp charset-normalizer coverage frozenlist grpcio `
#     httptools jiter lxml MarkupSafe mmh3 multidict numpy orjson pandas `
#     pendulum propcache pyarrow pybase64 pydantic google-re2 regex rpds-py `
#     tiktoken watchfiles websockets PyYAML yarl
#
#   # pywin32 ships DLLs with no cp tag, so the step above misses it:
#   uv pip install --python .venv\Scripts\python.exe --reinstall pywin32
#   .venv\Scripts\python.exe .venv\Scripts\pywin32_postinstall.py -install -silent
#
# Verify (do not trust exit codes; these are the real gates):
#   .venv\Scripts\python.exe -m pytest      # expect 260 passed, 3 skipped
#   .venv\Scripts\python.exe -m ruff check .
#
# ---------------------------------------------------------------------------
# Known 3.14 landmines already handled by the pins below
# ---------------------------------------------------------------------------
# chromadb : 1.1.1 (what a 3.13 resolve picks) uses pydantic.v1 and dies on
#            3.14's deferred annotations:
#              ConfigError: unable to infer type for attribute
#                           "chroma_server_nofile"
#            1.5.9 is pinned here because it works on 3.14.
#
# This set is a repaired install, not a clean resolve. It drifts from
# requirements.txt (tiktoken, websockets, onnxruntime and others moved). It is
# verified only on Windows + CPython 3.14.4.
#
# Upgrading any package here can silently reintroduce a 3.14-hostile version,
# because nothing upstream promises 3.14 support yet. Re-run pytest after any
# change to this environment.
#
# Provenance, 2026-09-04, CPython 3.14.4 on Windows: the pins below are a

# ===========================================================================
